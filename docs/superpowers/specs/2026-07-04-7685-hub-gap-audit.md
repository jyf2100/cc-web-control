# :7685 hub 现状 vs mockup · gap audit

- **日期**:2026-07-04
- **范围**:**仅 :7685 hub(多机多会话)**。:7684 板载(单机)明确不在范围内。
- **基准**:`.playwright-mcp/console-dashboard-separation-mockup.html`(用户提供的「控制台/看板分离 · 方案 A」多机 mockup)= :7685 设计基准,照搬,无需映射。
- **方法**:逐组件对照 mockup 类名/结构 vs :7685 现状代码(`dashboard.js` / `board_render.cjs` / `console.html` / `console_render.cjs` / `dashboard.css`)。

## 1. 结论先行 —— 为什么偏离

偏离**不在配色/tokens**(editorial 设计系统已全量落地:旧 token `--brand/--text/--muted` 0 残留、硬编码琥珀 0、深色规则 0),**也不在控制台** —— `console.html` 忠实实现了 mockup(Command Bridge / 主控 agent / Start·Stop·▾镜像 / hero-callout / term-screen / bottom-tabbar 全齐,`console_render.cjs` 无 `singleMachine` 简化逻辑)。

**偏离集中在看板,单一根因:`2026-07-04-single-machine-board-redesign-design.md` 植入的 `singleMachine` 分支。**

那份 spec §1 明文写:

> 实际 :7685 是**「单机多会话开发」**场景(一手数据):1 台机器 `mac-pro`,9 个会话…

**前提错误**。:7685 实为**多机多会话 hub**(用户 2026-07-04 明确纠正:「7685 是多机多会话,7684 才是单机多会话」)。spec 据错误前提在看板渲染器里加了「≤1 台机器 → 会话维度特化」,于是当 hub 只挂 1 台机器(本地常见)时,看板**自动降级成单机视图**,直接违背 mockup 的机器维度。

## 3. 根因代码落点

```
dashboard.js:156     singleMachine = machines.length>0 && Object.keys(machineIds).length<=1
dashboard.js:117-139 renderFleetSummary:单机走会话维度措辞,多机走机器维度
dashboard.js:140-148 buildCardLi:透传 singleMachine 给 buildCardInner
board_render.cjs:57  if (o.singleMachine) classes.push('card--single')
board_render.cjs:62  primaryName = o.singleMachine ? 会话名 : 机器名
board_render.cjs:63  secondary  = o.singleMachine ? cwd      : 会话名
```

**触发条件**:hub 注册的不同 `machine.id` 数 ≤ 1。
**影响面**:仅 :7685 hub board-grid 渲染路径。:7684 板载走 `detectMode → loop() → renderSessionList`(sessionList 单机列表,不碰 `buildCardInner`),**不受影响** —— 移除 `singleMachine` 只影响 :7685,符合「聚焦 :7685,:7684 不动」。

## 4. 修复建议 + 优先级

1. 🔴 **移除 `singleMachine` 分支** —— :7685 永远机器维度(机器名主标题 + 机器维度 fleet summary)。最小改动,直击根因,看板即刻对齐 mockup。
   - `dashboard.js`:删 `singleMachine` 判定,`renderFleetSummary` / `buildCardLi` 永远走多机分支。
   - `board_render.cjs`:`buildCardInner` 删 `o.singleMachine` 三元,永远 `primaryName=机器名 / secondary=会话名`,删 `card--single` 类。
   - 测试:`board_render.test.cjs` 的 `singleMachine` 用例改为「永远机器名」,同步更新。
2. 🟡 **`card__select` 取舍** —— 补渲染(对齐 mockup 卡片级多选)还是删 `dashboard.css:178` 死样式?现状卡片是 `<a>` click-to-navigate + term-input 扇出广播(`bc-count`),卡片级多选可能多余。
3. 🟢 **陈旧折叠 / cleanSummary 去留** —— mockup 没画,但针对真实陈旧数据(633h 僵尸)合理。保留作 mockup 运行时补充,还是严格照 mockup 删掉?

## 5. 待决策取舍点(用户拍板)

- **取舍 A**:`singleMachine` 移除后,当 :7685 本地只挂 1 台机器时,fleet summary 显示「▶0 ⏸0 ✕1 在线 1/1」(机器维度,信息量低)vs 现状「0 活跃 · 6 陈旧 · 1 异常」(会话维度,信息量高)。**多机 hub 定位下应取机器维度(对齐 mockup),即便 1 台机器。** —— 倾向移除,但需用户确认。
- **取舍 B**:`card__select` 多选框 —— mockup 设计意图 vs 现状 term-input 扇出替代。
- **取舍 C**:陈旧折叠 + cleanSummary —— 保留(运行时补充)vs 删除(严格照 mockup)。
